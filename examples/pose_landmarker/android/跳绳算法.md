# 跳绳计数算法说明 (Jump Rope Counting Algorithm)

本文档详细说明了当前跳绳计数器的核心算法逻辑、状态流转及动态适应机制。

## 1. 核心设计思路

本算法采用 **"基于肩部核心的动态波峰检测 (Shoulder-Based Dynamic Peak Detection)"** 方案。
相比于传统的踝部或髋部追踪，肩部在跳绳运动中（尤其是连续快速跳跃时）具有更稳定的垂直位移特征，且不易受腿部屈伸动作的干扰。

### 主要特性
*   **信号源**: 肩部中心点 (Shoulder Center Y)。
*   **自适应基准**: 自动计算并更新地面基准线 (Ground Baseline)。
*   **迟滞状态机**: 使用双阈值 (Up/Down Thresholds) 区分起跳与落地，防止临界值抖动。
*   **双重动态适应**:
    *   **动态幅度**: 根据用户实际跳跃高度自动调整触发阈值。
    *   **动态节奏**: 根据用户最近的跳跃频率自动调整最小计数保护间隔。

---

## 2. 数据处理流程

### 2.1 输入预处理 (Preprocessing)
1.  **输入数据**: 获取 Pose Landmark 中的 `Shoulder` (肩)、`Hip` (髋)、`Ankle` (踝) 的 Y坐标。
2.  **生理验证**: 检查 `Shoulder < Hip < Ankle` (Y轴向下) 等基本生理约束，过滤异常姿态。
3.  **平滑处理**: 使用指数移动平均 (EMA, alpha=0.3~0.5) 对原始坐标进行去噪平滑。
    *   `smoothY = (1 - alpha) * prevY + alpha * currY`

### 2.2 基准线计算 (Ground Baseline)
*   **校准期**: 前30帧作为校准阶段，计算肩部Y坐标的平均值作为初始 `groundY`。
*   **动态更新**: 当处于 `STATE_GROUND` (地面状态) 时，以缓慢的速率 (alpha=0.01) 更新 `groundY`，以适应摄像机微动或用户位置变化。
*   **提取抬升量 (Lift)**:
    *   `currentLift = groundY - smoothShoulderY`
    *   (注: 坐标系中 Y 轴向下，因此数值减小代表高度增加)

---

## 3. 状态机逻辑 (State Machine)

算法维护两个核心状态：`STATE_GROUND` (地面) 和 `STATE_AIR` (腾空)。

### 阈值定义
*   `currentJumpPeak`: 当前估计的跳跃波峰高度（动态变量）。
*   `upThreshold`: 起跳阈值 = `currentJumpPeak * 0.60`。
*   `downThreshold`: 落地阈值 = `currentJumpPeak * 0.35`。

### 状态流转
1.  **起跳判断 (Ground -> Air)**
    *   条件: `currentLift > upThreshold`
    *   动作:
        *   切换状态至 `STATE_AIR`。
        *   记录 `airStartTime`。

2.  **落地判断 (Air -> Ground)**
    *   条件: `currentLift < downThreshold`
    *   动作: 
        *   检查有效性 (Validation)。
        *   若有效，`count++`。
        *   切换状态至 `STATE_GROUND`。
        *   触发动态参数更新。

3.  **有效性验证 (Validation)**
    *   **最小腾空时间**: `airDuration > 80ms` (防止极快的高频噪点)。
    *   **冷却时间**: `timeSinceLastJump > minInterval` (防止一次跳跃被误判为多次)。

---

## 4. 动态自适应机制 (Dynamic Adaptation)

为了适应不同用户（快跳/慢跳、高跳/低跳）的差异，算法实时的调整核心参数。

### 4.1 动态幅度 (Dynamic Amplitude)
适应用户的跳跃高度疲劳或发力变化。
*   **波峰衰减**: 每一帧 `currentJumpPeak *= 0.99` (模拟疲劳衰减)。
*   **波峰更新**: 如果 `currentLift > currentJumpPeak`，立即更新 `currentJumpPeak = currentLift`。
*   **落地更新**: 成功计数时，使用实际跳跃高度加权更新：
    *   `currentJumpPeak = currentJumpPeak * 0.7 + actualJumpHeight * 0.3`

### 4.2 动态节奏 (Dynamic Interval)
适应用户的跳绳速度（如双摇 vs 慢跑）。
*   **历史记录**: 维护最近 5 次跳跃的时间间隔队列 `recentIntervals`。
*   **计算逻辑**:
    *   `avgInterval` = 最近 5 次间隔的平均值。
    *   `minInterval` = `avgInterval * 0.6`。
*   **限制**: `minInterval` 被限制在 `[200ms, 800ms]` 范围内。

---

## 5. 追踪与防干扰 (Tracking & Anti-Interference)

为了防止背景人物或误检导致的“幽灵计数” (Ghost Counters)。

### 5.1 追踪策略 (Kotlin层)
1.  **面积过滤**: 忽略面积小于屏幕 2% 的人体检测框 (Likely far away or false positive)。
2.  **主用户优先**: 对所有检测框按 **面积大小降序排列**，优先处理最大的目标。
3.  **IoU 匹配**: 使用 Intersection over Union (IoU) 算法将当前帧检测框与上一帧的追踪器匹配，确保 ID 稳定性。

---

## 6. 附录：核心参数表

| 参数 | 默认值/范围 | 说明 |
| :--- | :--- | :--- |
| `alpha` (Smoothing) | 0.3 - 0.5 | 关键点平滑系数 |
| `upThresholdRatio` | 0.60 | 起跳触发比例 (相对于 Peaks) |
| `downThresholdRatio` | 0.35 | 落地触发比例 (相对于 Peaks) |
| `minAirDuration` | 80 ms | 最小腾空时间 |
| `poseAreaFilter` | 0.02 (2%) | 忽略小于此比例的检测框 |
