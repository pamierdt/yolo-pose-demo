# 跳绳计数算法说明 (Jump Rope Counting Algorithm)

本文档详细说明了跳绳计数器的核心算法逻辑、状态流转及动态适应机制。

## 1. 核心设计思路

本算法采用 **"基于髋部核心的动态波峰检测 (Hip-Based Dynamic Peak Detection)"** 方案。
相比于传统的踝部追踪（易被绳子遮挡）或肩部追踪（手臂摆动干扰大），髋部（Hip）在跳绳运动中具有最稳定的垂直位移特征，且能真实反映身体重心的变化。

### 主要特性
*   **信号源**: 髋部中心点 (Hip Center Y)。
*   **归一化**: 使用躯干长度 (Shoulder to Hip) 作为参考尺，消除距离和身高差异。
*   **自适应基准**: 自动计算并更新地面基准线 (Ground Baseline)。
*   **迟滞状态机**: 使用双阈值 (Up/Down Thresholds) 区分起跳与落地，防止临界值抖动。
*   **双重动态适应**:
    *   **动态幅度**: 根据用户实际跳跃高度自动调整触发阈值。
    *   **动态节奏**: 根据用户最近的跳跃频率自动调整最小计数保护间隔。

## 2. 数据处理流程

### 2.1 输入预处理 (Preprocessing)
1.  **输入数据**: 获取 Pose Landmark 中的 `Shoulder` (肩)、`Hip` (髋)、`Ankle` (踝) 的 Y坐标。
2.  **生理验证**: 检查 `Shoulder < Hip < Ankle` (Y轴向下) 等基本生理约束，过滤异常姿态。
3.  **平滑处理**: 使用指数移动平均 (EMA) 对原始坐标进行去噪平滑。

### 2.2 归一化与自适应阈值
*   **归一化逻辑**：算法通过计算 **躯干长度 (Trunk Length)** = $|Hip_Y - Shoulder_Y|$ 作为参考尺。
*   **异常保护**：对躯干长度进行合理性检查（0.02 < L < 0.8），既能适应远距离小目标，也能适应近距离半身特写，同时过滤掉无效的姿态数据。
*   **适应性**：无论小朋友离摄像头远（躯干短）还是近（躯干长），判定阈值都是躯干长度的一个比例。
*   **自适应系数**：根据历史跳跃高度自动调整。
    *   **极小幅度** (快速小跳): 系数降至 $0.04 \times L$。
    *   **小幅度** (疲劳/常规): 系数降至 $0.06 \times L$。
    *   **大幅度**: 系数升至 $0.12 \times L$。
    *   **默认**: $0.10 \times L$。

### 2.3 基准线计算 (Ground Baseline)
*   **校准期**: 前3帧作为校准阶段，计算髋部Y坐标的平均值作为初始 `groundY`。
*   **动态更新**: 当处于 `STATE_GROUND` (地面状态) 时，以平滑系数 (alpha=0.05) 更新 `groundY`，以适应摄像机微动或用户位置变化。
*   **提取抬升量 (Lift)**:
    *   `currentLift = groundY - smoothHipY`
    *   (注: 坐标系中 Y 轴向下，因此数值减小代表高度增加)

---

## 3. 状态机逻辑 (State Machine)

算法维护两个核心状态：`STATE_GROUND` (地面) 和 `STATE_AIR` (腾空)。

### 阈值定义
*   `currentJumpPeak`: 当前估计的跳跃波峰高度（动态变量，随时间衰减）。
    *   *优化*：针对小幅度跳跃，放宽波峰下限约束至 `threshold * 1.5`。
*   `upThreshold`: 起跳阈值 = `currentJumpPeak * 0.60`。
*   `downThreshold`: 落地阈值 = `currentJumpPeak * 0.35`。

### 状态流转
1.  **起跳判断 (Ground -> Air)**
    *   条件: `currentLift > upThreshold`
    *   动作:
        *   切换状态至 `STATE_AIR`。
        *   记录 `airStartTime`。

2.  **落地判断 (Air -> Ground)**
    *   条件: `currentLift < downThreshold`
    *   动作: 
        *   检查有效性 (Validation)。
        *   若有效，`count++`。
        *   切换状态至 `STATE_GROUND`。
        *   触发动态参数更新（将本次跳跃高度加入历史记录）。

3.  **有效性验证 (Validation)**
    *   **最小腾空时间**: `airDuration > 80ms` (防止极快的高频噪点)。
    *   **冷却时间**: `timeSinceLastJump > minInterval` (防止一次跳跃被误判为多次)。

## 4. 硬件部署与优化建议 (针对瑞芯微平台)

在瑞芯微（Rockchip）平台（如RK3588, RK3568, RV1126等）上针对幼儿园场景部署时：

### A. 算法部署架构
1.  **检测**: 使用 **YOLOv8-Pose** 或 **YOLOv11-Pose** (需转为 ONNX -> RKNN)，运行在 NPU 上。
    *   推荐输入尺寸: **640x640** (多人) 或 **320x320** (单人特写/追求极速)。
2.  **跟踪**: 使用 **ByteTrack** 进行多目标跟踪，为每个 ID 独立维护一个计数器实例。
3.  **计数**: 使用本文档描述的 **C++ 状态机算法**，运行在 CPU 上（计算量极小，无负担）。

### B. 针对“幼儿园小朋友”的特殊优化
1.  **“假跳” (垫脚/屈膝)**：
    *   利用 **髋部 (Hip)** 作为核心指标，而非肩部或头部，能有效过滤单纯的屈膝动作。
    *   辅助验证：只有当踝部 (Ankle) 也显著上升时才确认为有效跳跃（防作弊逻辑）。
2.  **动作不规律/节奏乱**：
    *   **动态节奏适应**: 算法会自动计算最近5次跳跃的平均间隔，并将最小冷却时间 (`minInterval`) 设为平均间隔的 60%。
    *   这意味着算法能自动适应小朋友从“慢跳”突然加速到“快跳”的变化。
3.  **绳子绊倒/停顿**：
    *   利用 **平滑滤波** 和 **迟滞比较器**，即使动作中断或有微小晃动，也不会产生误计数。

## 5. C++ 核心逻辑伪代码

```cpp
// 核心更新函数 (简化版)
int update(float shoulderY, float hipY, float ankleY, double timestamp) {
    // 1. 多帧平滑 (Smoothing)
    float smoothHip = hipSmoother.push(hipY);
    
    // 2. 归一化 & 动态阈值
    float trunkLen = abs(hipY - shoulderY);
    // 异常保护：过滤无效姿态
    if (trunkLen < 0.02 || trunkLen > 0.8) return count;

    float threshold = trunkLen * getAdaptiveCoef(); // 0.04 ~ 0.12
    
    // 3. 动态基准线 (只在地面更新)
    if (state == GROUND) {
        groundY = 0.95 * groundY + 0.05 * smoothHip;
    }
    
    // 4. 计算抬升高度 (注意 Y轴向下)
    float currentLift = groundY - smoothHip;
    
    // 5. 更新波峰包络 (用于迟滞比较)
    // 衰减旧波峰，更新新波峰
    currentPeak = max(currentPeak * 0.99, currentLift);
    // 优化：放宽下限以适应小幅度跳跃
    if (currentPeak < threshold * 1.5) currentPeak = threshold * 1.5;

    float upThresh = currentPeak * 0.60;
    float downThresh = currentPeak * 0.35;
    
    // 6. 状态机流转
    if (state == GROUND) {
        if (currentLift > upThresh) {
            state = AIR; // 起跳
        }
    }
    else if (state == AIR) {
        if (currentLift < downThresh) {
            // 落地
            if (checkCoolDown(timestamp)) {
                count++;
                addJumpHistory(currentPeak); // 更新自适应历史
            }
            state = GROUND;
        }
    }
    
    return count;
}
```
